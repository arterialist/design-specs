High-throughput transport benchmark

Profiling session across concurrency levels, memory bounds, and latency plateaus.

Executive benchmark summary

The connection-pooled transport operates at 18x lower CPU utilization and maintains resident memory within 120 MB under peak load, compared to 816 MB in the baseline single-threaded runner.

Scaling worker concurrency from 1 to 4 sessions reduces overall sweep duration from 151 s down to 35 s. Concurrency beyond 8 worker sessions encounters host round-trip serialization and yields diminishing returns. Four worker threads is the recommended production setting.

Key architectural optimizations

  • Iterative tree traversal. Replaced recursive generator tree traversals with an iterative loop and revision caching, eliminating 330 million generator frames per 200 requests.
  • Cyclic reference cleanup. Explicitly clearing parent and child document links on node replacement allows the garbage collector to immediately release 22 MB buffers by reference counting.
  • Shared authentication session pool. Pre-authenticates worker threads in parallel and dispatches chunked workload items from a thread-safe synchronized queue.
  • Deterministic key sorting. Forces lexicographical sorting on multi-page queries, preventing duplicate item shifts across pagination intervals.

Concurrency scaling limits

Throughput gains flatten beyond eight concurrent sessions. Two primary physical constraints set this ceiling:

  1. Authentication handshakes: Establishing initial session credentials requires 6 to 9 seconds per thread, expanding to 14 seconds when more than 12 sessions negotiate simultaneously.
  2. Serial work chunk size: The single longest query partition requires 8 seconds to fetch and cannot be subdivided further, forming an absolute execution floor.

Deploying four to six worker sessions captures 90% of maximum throughput while preserving minimal memory overhead.
